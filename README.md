# TravelMate-AI

An intelligent AI-powered travel planner built with IBM Granite, FastAPI, and React.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React 18 + Vite + Tailwind CSS |
| Backend | Python 3.12 + FastAPI |
| AI Model | IBM Granite (`ibm/granite-4-h-small`) via watsonx.ai |
| Database | IBM Cloudant Lite |
| Maps | OpenStreetMap + Leaflet |
| Weather | Open-Meteo API (free, no key required) |
| Frontend Deploy | Vercel |
| Backend Deploy | Render |

## Features

- 🗺️ AI destination recommendations (IBM Granite)
- 📅 Personalized travel itineraries (IBM Granite)
- 💰 Budget estimation with clear "(estimated)" labels
- 🚌 Transport recommendations
- 🏨 Accommodation suggestions
- 🌤️ Live weather information (Open-Meteo)
- 🗺️ Interactive maps (Leaflet + OpenStreetMap)
- 💬 Travel chat assistant (IBM Granite)

## Local Development

### Prerequisites

- Python 3.12 (Anaconda `travelmate` environment)
- Node.js 24+
- Git

### 1. Clone the repository

```bash
git clone https://github.com/your-username/TravelMate-AI.git
cd TravelMate-AI
```

### 2. Backend setup

```bash
cd backend

# Activate the travelmate conda environment
conda activate travelmate

# Install dependencies
pip install -r requirements.txt

# Copy environment template and fill in your credentials
cp .env.example .env
# Edit .env with your IBM Cloud API key and Cloudant credentials

# Start the backend
uvicorn app.main:app --reload --port 8000
```

Backend will be available at: `http://localhost:8000`
Health check: `http://localhost:8000/health`
API docs: `http://localhost:8000/docs`

### 3. Frontend setup

```bash
cd frontend

# Install dependencies
npm install

# Copy environment template
cp .env.example .env
# Edit .env — set VITE_API_BASE_URL=http://localhost:8000/api/v1

# Start the dev server
npm run dev
```

Frontend will be available at: `http://localhost:5173`

## Environment Variables

### Backend (`backend/.env`)

See [`backend/.env.example`](backend/.env.example) for all required variables.

Key variables:
- `WATSONX_API_KEY` — IBM Cloud API key
- `WATSONX_PROJECT_ID` — watsonx.ai project ID
- `CLOUDANT_URL` — IBM Cloudant instance URL
- `CLOUDANT_APIKEY` — IBM Cloudant API key
- `CORS_ORIGINS` — comma-separated allowed frontend origins

### Frontend (`frontend/.env`)

See [`frontend/.env.example`](frontend/.env.example) for all variables.

Key variable:
- `VITE_API_BASE_URL` — backend API base URL (e.g. `http://localhost:8000/api/v1`)

## Deployment

### Backend → Render

1. Push code to GitHub
2. Create a new Web Service on [Render](https://render.com)
3. Connect your GitHub repository
4. Set root directory to `backend/`
5. Set secret environment variables in the Render dashboard (see `.env.example`)
6. Deploy

### Frontend → Vercel

1. Create a new project on [Vercel](https://vercel.com)
2. Connect your GitHub repository
3. Set root directory to `frontend/`
4. Set `VITE_API_BASE_URL` to your Render backend URL in Vercel environment variables
5. Deploy

## Important Notes

- All prices generated by IBM Granite are **estimates** and are clearly labeled `(estimated)` in the UI
- Live weather data from Open-Meteo is labeled `Live weather`
- IBM credentials are **never** stored in frontend code or committed to GitHub
- The health check endpoint (`/health`) works independently of IBM credentials
